# [ARM64](https://docs.u-boot.org/en/latest/arch/arm64.html)

## 概要

arm64版U-Bootの初期移植版はハードウェアが利用可能になる前に開発されたため、
最初にサポートされたプラットフォームはARMv8向けの"Foundation"および"Fast Model"でした。
現在では、U-Bootは組み込み開発ボードからサーバーに至るまで、64ビット対応のさまざまな
ARMハードウェア上で動作しています。

### 注

1. U-Bootは投入された例外レベルに関係なく実行可能ですが、U-Bootが従来のファームウェアの
   役割の一部（ハードウェアの初期設定、CPUエラッタの回避、SMPの起動など）を担う場合は
   EL3で入ることが推奨されます。U-Bootの主な目的がブートローダである場合はEL2で入ることが
   できます。OSに入る前に、より低い例外レベルに遷移することも可能です。ARMv8-Rについては、
   このアーキテクチャにはS-EL3が存在しないため、S-EL1で起動することを推奨します。
2. arm64版のU-BootはAArch64-gccでコンパイルされます。AArch64-gccはrelaリロケーション
   形式を使用しており、Scott Wood氏によるツール（tools/relocate-rela）を使用して、
   u-boot.binへのrelaの初期加数 (addend) をエンコードします。実行後、U-Bootは再度宛先へ
   リロケーションされます。
3. 以前のバージョンのLinuxカーネルでは、FDTを2MBの境界に配置し、かつカーネルイメージと
   同じ512MBのセクション内に配置する必要があったため、fdt_highを定義する必要がありました。
   カーネルバージョン4.2以降、LinuxはDTの配置に関する制限が緩和され、メモリ内の任意の場所に
   配置できるようになりました。詳細については、linux/Documentation/arm64/booting.txtを
   参照してください。
4. セカンダリプロセッサを起床させるためにスピンテーブルが使用されます。セカンダリプロセッサ用の
   カーネルエントリポイントを格納するために1つのロケーション（またはプロセッサごとの
   ロケーション）が定義されます。start.S内でセカンダリプロセッサがslave_cpu分岐の実行に
   入った直後、そのロケーションにアクセス可能であり、かつその値がゼロでなければなりません。
   このロケーションのアドレスはDTSのcpuノードにエンコードされています。Linuxカーネルは
   セカンダリプロセッサのエントリポイントをそこに格納し、セカンダリプロセッサを起床させる
   ためにイベントを送信します。詳細については、linux/Documentation/arm64/booting.txt を
   参照してください。
5. 汎用ボードがサポートされています。
6. aarch64とaarch32の固有コードを区別するためにCONFIG_ARMV8ではなくCONFIG_ARM64が
   使用されています。

## MMU

U-BootはMMUの設定に単純なページテーブルを使用します。最大メモリアドレスに基づいて
仮想アドレスに可能な限り少ないビット数を使用します（`get_tcr()`内のロジックを参照）。
これが39ビット未満の場合、MMUはアドレス変換に3レベルしか使用しません。

他のすべてのプラットフォームと同様、ARM64上のU-Bootでは仮想アドレスと物理アドレスの
1:1マッピングが使用されます。一般に、MMUが有効になるとメモリマップは変わらないことが
想定されます。

### ソフトウェア・ページテーブル・ウォーカー

U-Bootによって生成されたページテーブルは組み込みの`dump_pagetable()`関数と
`walk_pagetable()`関数（前者は後者の単純なラッパーです）を使用してデバッグすることが
できます。たとえば、`setup_pgtables()`の最初の呼び出後に`setup_all_pgtables()`に
次のようなコードを追加することができます。

```c
dump_pagetable(gd->arch.tlb_addr, get_tcr(NULL, NULL));
```

```c
// pagetableを渡り歩いて各メモリ領域ごとにcb()を呼び出す
// addr: 渡り歩くテーブルのアドレス
// tcr: TCRレジスタ値
// levle: テーブルのカレントレベル
// cb: 各領域ごとに呼び出すコールバック関数
// priv: コールバック関数に渡すプライベートデータ
void __pagetable_walk(u64 addr, u64 tcr, int level, pte_walker_cb_t cb, void *priv)
```
